# Emails con Resend: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cinco emails con el estilo oscuro de la marca (bienvenida, voucher, aviso a tesorería, aviso a recepción y ladrillo confirmado), email obligatorio en los formularios y nada que mande a WhatsApp.

**Architecture:** Las plantillas viven en la API como funciones puras que devuelven `{ asunto, html }` sobre un marco común con tablas y estilos inline. Los formularios pasan de "contactoTipo + contacto" a "email obligatorio + whatsapp opcional" (columna nueva, migración aditiva). Panel y web se adaptan al contrato nuevo.

**Tech Stack:** NestJS 11 + Prisma 7 + vitest, Resend (ya instalado); Astro (web); Angular Material (panel).

**Spec:** `docs/superpowers/specs/2026-11-17-emails-design.md`

## Global Constraints

- Estilo: fondo `#000000`, texto `#f5f5f0`, gris `#a3a3a3`, verde hoja `#a0d062`, bloque `#0a0a0a`, franja final `#0c74b8` con "¡La iglesia sos vos!". Ancho máximo 560 px, una columna, maquetado con `<table>` y estilos inline, sin CSS externo ni SVG. Versículo centrado con comillas grandes verdes, **sin borde lateral**. Botones redondeados verde hoja con texto negro.
- Logo: `SITE_URL/logo-email.png` (PNG de 192 px generado desde `apps/web/public/logo.svg`).
- Todo dato que escribió una persona pasa por `escapar` antes de entrar al HTML.
- Ningún texto (emails, instrucciones de pago, formularios) menciona WhatsApp como canal de la iglesia.
- Los emails salen en segundo plano: un fallo de Resend nunca hace fallar el formulario ni la confirmación.
- `RECEPCION_EMAIL` y `TESORERIA_EMAIL` aceptan varias direcciones separadas por coma. El email del voucher lleva `replyTo` = las direcciones de `TESORERIA_EMAIL`.
- Asunto del voucher: `Tu voucher Pro Templo Nº <n>` (`numeroVoucher(n)`).
- Contrato público nuevo: `CrearVisita` y `CrearVoucher` pierden `contactoTipo`/`contacto` y ganan `email: string` (obligatorio, formato email, máx. 120) y `whatsapp?: string` (opcional, mínimo 10 dígitos si viene). En la base: `contacto` = email, `contactoTipo` = `'email'`, columna nueva `whatsapp` (nullable) en `visitas` y `vouchers`.
- Textos nuevos en `TextosSitio`: `versiculoBienvenida: { texto: string; cita: string }` (por defecto `"Vengan a mí todos ustedes que están cansados y agobiados, y yo les daré descanso."` / `Mateo 11:28`) y `mapaUrl: string` (por defecto `''`; vacío = `https://www.google.com/maps/search/?api=1&query=` + `encodeURIComponent(direccion + ', CABA')`).
- Variables nuevas de la API: `PANEL_URL` (por defecto `http://localhost:4200`); `EMAIL_FROM` por defecto `CCVida Capital <hola@ccvidacapital.org>`.
- Voseo rioplatense en todos los textos.

## Review Focus

- Un nombre con `<script>` o `"` en cualquier formulario: aparece escapado en los 5 emails. → test en Task 1.
- Transferencia sin `datosTransferencia` cargados en el panel: el email no queda con un bloque vacío; dice que tesorería le manda los datos respondiendo el email. → test en Task 1.
- `TESORERIA_EMAIL` vacío: el voucher se crea, el aviso no sale y el email a la persona sale sin `replyTo` (no con un `replyTo` vacío). → test en Task 2.
- Confirmar un voucher dos veces o confirmar uno sin email válido: no se manda un segundo "ladrillo confirmado" ni falla. → test en Task 2.
- Formulario viejo cacheado en un navegador que todavía manda `contactoTipo`/`contacto`: la API responde 400 con un mensaje claro ("Escribí tu email…"), no 500. → test en Task 2.

**Interfaces:**
- Produces (en `plantillas.ts`, todas devuelven `{ asunto: string; html: string }`):
  - `bienvenidaVisita(d: { nombre: string; reunion: string; direccion: string; barrio?: string; mapaUrl: string; versiculo: { texto: string; cita: string }; sitioUrl: string })` — asunto `¡Te esperamos, <primer nombre>!`
  - `voucherRegistrado(d: { nombre: string; numero: number; montoUsd: number; formaPago: FormaPago; datosTransferencia: string; sitioUrl: string })` — asunto `Tu voucher Pro Templo Nº <n>`; incluye las instrucciones según la forma de pago, "Respondé este email con la foto del comprobante" (transferencia) y "Tu ladrillo aparece en la pared cuando tesorería confirma el pago."; link al estado del voucher.
  - `avisoTesoreria(d: { nombre: string; numero: number; montoUsd: number; formaPago: FormaPago; email: string; whatsapp: string | null; panelUrl: string })` — botón "Revisar en el panel" → `${panelUrl}/vouchers`.
  - `avisoRecepcion(d: { nombre: string; email: string; whatsapp: string | null; intereses: string[]; panelUrl: string })` — botón → `${panelUrl}/visitas`.
  - `ladrilloConfirmado(d: { nombre: string; numero: number; sitioUrl: string })` — asunto `¡Tu ladrillo ya está en la pared!`; botón a `${sitioUrl}/pro-templo`.
  - `urlMapa(direccion: string, mapaUrl: string): string`
  - `marco(contenido: string, d: { sitioUrl: string; pie: string }): string` en `marco.ts`.
- `EmailService.enviar(para: string, asunto: string, html: string, opciones?: { responderA?: string }): Promise<void>`; `para` y `responderA` se parten por coma, se recortan y se descartan vacíos; si `para` queda vacío no se manda; `replyTo` solo si hay direcciones.
